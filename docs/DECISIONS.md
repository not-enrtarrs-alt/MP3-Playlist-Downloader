# Decisions

- M0: This is a fresh start: no `src/`, project metadata, tests, or progress documents existed.
- M0: Python package installation is needed for PySide6 and pytest; tests will remain offline after installation.
- M0: Initial writable-directory probe failed due to a missing helper; the corrected independent probe succeeded.
- M0: No historical hash exists for `main_fixed.py`; its initial SHA-256 is recorded in TOOLNOTES for subsequent verification.
- M0: The version-1 database initializer rejects unsupported schema versions rather than guessing or downgrading them; migrations beyond version 1 are not yet needed.
- M0: Doctor treats missing ffmpeg/ffprobe/mp3gain as warnings; future download actions must block without ffmpeg. Playlist, queue, demo, packaging, and actual equalization are deferred to their specified milestones.
- M0: A Qt offscreen event-loop smoke test verifies bootstrap without requiring a visible desktop; interactive Windows UI behavior remains unverified.
- M1: Treat explicitly titled `[Private video]` and `[Deleted video]` entries as unavailable in addition to missing titles; yt-dlp can emit these sentinel titles.
- M1: Cancelling a yt-dlp metadata fetch discards its result before database writes; the underlying blocking request cannot be interrupted by the yt-dlp API and may continue in the background until it returns.
- M1: Suppress raw yt-dlp diagnostic output and surface only classified safe errors; upstream diagnostics may contain cookie paths or secrets.
- M2: A kept extra can still be recycled after an explicit later user delete request; it is never automatically deleted. This reconciles the kept label with the specified delete-selected action.
- M2: ID3v2.3 does not support UTF-8 text encoding; request UTF-8 for new frames and let mutagen serialize them in a v2.3-compatible encoding rather than writing invalid v2.3 tags.
- M2: Split the download pipeline into `youtube/download.py` instead of expanding `youtube/client.py`, keeping the modules focused and under the approximate 300-line limit.
- M2: Startup cleanup recognizes only `.tmp-` plus 32 hexadecimal characters and a suffix, the pattern generated by this app; looser names may belong to the user and are never removed automatically.
- M2: Split scan, delete and queue worker bridges into `ui/library_workers.py` to keep thread ownership explicit and avoid overgrowing `ui/workers.py`.
- M2: Use `ui/library_controller.py` to coordinate asynchronous scans and dialogs without growing the main window beyond the approximate module size limit.
- M2: Use `ui/queue_controller.py` for the queue UI and recovery lifecycle. Until overwrite is implemented in M4, a configured overwrite run is blocked rather than silently skipping existing files.
- M2: Demo uses ffmpeg to generate its temporary silent MP3; ffmpeg is already a runtime dependency. Demo statuses simulate equalization without modifying audio; no mp3gain or network is used.
- M3: With both tagging and equalization failures, retain `error_kind='tag'` and append the safe equalization warning; the schema permits only one warning kind and both failures remain visible.
- M3: Split tab widgets and diagnostic workers into `ui/settings_tabs.py` and `ui/settings_workers.py` so the dialog stays maintainable and near the module-size guideline.
- M3: Test cookies uses the currently selected playlist; if none is selected, the dialog asks the user to select one rather than relying on a hard-coded public playlist that may disappear.
- M3: A dedicated equalization controller coordinates the irreversible worker and its cancel/close lifecycle, keeping it separate from download queue state.
- M3: A full-suite run exposed a fresh-database race between GUI schema initialization and recovery. Start recovery only after initialization, and avoid repeatedly changing an already-WAL database's journal mode.
- M3: Move playlist open/remove actions into `ui/playlist_actions.py` to keep the growing main window near the specified module-size limit without changing behavior.
- M3: Two transient provider rate limits interrupted patch attempts; independent acceptance tests ran successfully, and documentation resumed after the tool recovered.
- M4: `queue_rate_limit_streak` counts the initial rate limit as 1, so retries are allowed while the streak is 1–3 and blocked at 4 (the initial pause plus three immediately rate-limited automatic attempts).
- M4: A queued downloaded row represents a previously confirmed overwrite; this persists the user's choice without introducing a separate queue table. Manual re-download of removed or unavailable rows is disabled to keep queued eligibility unambiguous.
- M4: Before recycling a tracked overwrite, compare its file identity and metadata with the pre-download snapshot; refuse replacement if it changed, lies outside its playlist folder, or is also tracked by another video.
- M4: Implement manual linking in `linking.py` to keep the service facade small. Symlinked or multiply hard-linked sources are copied rather than adopted, protecting files outside the playlist folder from in-place tagging.
- M4: Coordinate manual link and album-retag workers in `ui/edit_controller.py`; closing waits for the active file operation to finish so the application lock is not released early.
- M4: Transient provider rate limits interrupted tool calls; independent work continued and the focused tests were rerun successfully after recovery.
- M4: During a modal extra-file review, defer automatic resume until the dialog closes so user file decisions cannot overlap a download.
- M4: Adopting a chosen extra tags it in place as specified before recycling any old tracked file; if that recycle fails, the old row stays unchanged and the selected extra remains on disk, though its tags may already have changed.
- M4: On confirmed close after a worker finishes, skip scheduling a new folder scan; otherwise it could outlive the window and application lock.
- M5: Add `scripts/launcher.py` as a tiny PyInstaller entry point: freezing the package's `__main__.py` directly would break its relative imports.
- M5: Reuse an already-installed editable package and dependencies without contacting pip, allowing offline builds. Refuse to overwrite an existing onedir output and use unique PyInstaller work directories to preserve prior artifacts.
- M5: The first offline build failed because Windows PowerShell stripped embedded quotes in a Python `-c` dependency probe. Use `scripts/dependency_probe.py` instead; no output artifacts were produced.
- M5: Replace the M2 demo's ffmpeg requirement with a tiny compressed, locally generated silent MP3 fixture embedded in `demo.py`; the offline demo now works even when ffmpeg is absent.
- M5: Do not pass PyInstaller `--noconfirm`: if another process creates the onedir destination during a build, PyInstaller must not silently remove it.
- M5: Preserve the initial onedir build under a unique sibling name before rebuilding with final diagnostics, demo and documentation changes; no previous artifacts are deleted.
- M5: Move redaction to a standard-library-only module so `doctor` can sanitize tool help without requiring PySide6 to import successfully.
- M5: Repeated transient provider rate limits interrupted tool calls; independent checks were run after recovery and no existing files were discarded.
- M5: No user playlist or cookies were supplied and mp3gain/Inno Setup are absent. Do not guess a playlist or claim a real download/installer smoke test; leave M6 to verify with explicitly supplied prerequisites or document the limitation.
- M6: Preserve the user's `docs/MANUAL_TEST.md` results verbatim; they report passing playlist, local-file, gain and installer checks on their test environment, but also report a failed real download and incomplete album progress. Local discovery still finds no mp3gain or Inno Setup, so those user-reported results are not independently reproduced here.
- M6: Use explicitly paired Qt light/dark foreground and background colors instead of relying on Windows' potentially mixed standard palette; keep the specified status colors and verify contrast and rendering offline.
- M6: The selected-row contrast check failed after the first palette pass; defer that independent theme adjustment while fixing the separately reported album-progress issue, then return to the contrast test.
- M6: An offline reproduction with the user's configured ffmpeg showed yt-dlp thumbnail conversion failing after successful audio extraction. Preserve the MP3 only when yt-dlp's postprocessor hooks prove audio extraction finished and thumbnail conversion was active; never salvage an uncertain or partial audio conversion.
- M6: Repeated transient provider rate limits interrupted tool calls; tests and independent verification resumed after recovery. Preserve the user's manual results and prior onedir builds.
- M6: Do not claim the reported real-download failure is resolved solely from synthetic reproduction. The updated onedir is built, but M6 acceptance remains blocked until a real track is retested; the prior user data and manual-test annotations remain untouched.
- Title cleanup: The user explicitly superseded the original raw-title rule for titles with an official/officiel marker. Match the credited primary artist to the uploader case/punctuation-insensitively; leave mismatched or ambiguous artist-prefixed titles unchanged. Preserve existing Topic behavior when no marker is present.

- Title cleanup: Manual file links retain their specified source-derived or adopted filenames; the shared cleanup still applies to their title tags. New downloads use the cleaned title for filenames.
- Title cleanup: For qualifying official videos, recognizable remix, remaster, live and version annotations are metadata rather than part of the song name; remove those while preserving ambiguous parenthetical song-name text.
- Title cleanup: Transient provider rate limits interrupted tool calls; focused offline tests were rerun after recovery. Malformed brackets and uploader mismatches are deliberately left unchanged.
